# Start here: AOS Acceleration Chamber

Read `IDEA.md` first for the product and interaction model. Then use `DESIGN.md` as the visual authority.

Use the images under `references/nous/` and `references/tiktok/` as mood and composition references only. Do not copy Nous artwork, TikTok text, creator identity, branding, or exact layouts.

Build an actual interactive interface in HTML/CSS/SVG or React-native web components. Use deterministic illustrative state. This design pass has no backend requirement.

## The combination

- Nous/Hermes gives the interface restraint: severe cobalt/white fields, thin contemporary type, hard edges, sparse image rhythm, calm perimeter.
- Technological accelerationism gives it behaviour: recursive delegation, compressed time, rising throughput, competing branches, mutation, and visible generations.
- Singularity is a functional convergence state: many agents, models, and evidence paths compress into a consequential but inspectable decision.
- Cyberpunk contributes infrastructure, command surfaces, model/runtime telemetry, and hostile-system tension—without neon-street, hologram, CRT, or glitch clichés.
- **Per aspera ad astra** becomes vertical hierarchy: objective and constraints below, swarm and mutation through the middle, unresolved frontier above.

The TikTok frames are not a request to reproduce an edit. Extract their spatial ideas—large technological scale, compressed time, recursive systems, gravitational convergence, and warped infrastructure—then express those ideas through real AOS data.

The result should feel like serious research infrastructure under extreme intellectual velocity. It should not look retro, mystical, ornamental, or “AI generated.”

Do not present AOS as already being ASI. The singularity is a long-horizon product idea and a functional interface metaphor for convergence and successive generations.

## First surface

Design `#/swarm` first at:

- 1440 × 900 desktop
- 390 × 844 mobile

The desktop surface must include:

1. A narrow global rail.
2. One dominant acceleration field showing a hierarchical swarm, not a decorative node cloud.
3. Realistic illustrative agent state: task, parent, harness, model, status, tokens, estimated cost, elapsed time, dependencies, and evidence.
4. A context inspector that appears only after selection.
5. A collapsible bottom CLI sheet.
6. A quiet perimeter and one locally intense active path.

On mobile, replace the spatial graph with ordered stages and expandable hierarchical lists. Do not shrink the desktop graph.

## Remaining routes

Once the swarm language works, extend it consistently:

- `#/missions` — active research objectives and generation velocity.
- `#/intake` — goal, context, documents, constraints, ambiguity, and definition of done.
- `#/evidence` — provenance, claims, dissent, contradictions, and downstream use.
- `#/synthesis` — competing branches compressing into a conclusion with objections attached.
- `#/evolution` — baseline/candidate generations, rule changes, traces, metric deltas, rollback.
- `#/capabilities` — nonhuman routing topology for workers, models, skills, MCP, plugins, and generated tools.
- `#/memory` — global/project/agent stores, inheritance, expiry, isolation, and policy.

## Reject the result if

- it resembles a generic admin dashboard;
- it becomes retro-futurist, Y2K, or a sci-fi game HUD;
- it is an empty editorial poster rather than an operational interface;
- its graph is unreadable or merely decorative;
- it copies the Nous reference;
- singularity is represented by stock black-hole wallpaper;
- every screen is crowded;
- atmosphere obscures agent hierarchy or live resource use.

## Usability proof

A user should be able to answer these questions within seconds:

- What goal is the system pursuing?
- Who is working now?
- Who delegated each task?
- Which harness and model is each active worker using?
- What are the tokens, cost, and elapsed time?
- What evidence has been produced?
- Where is the bottleneck or human intervention?
- How did this run change the next generation?
